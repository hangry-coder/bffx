# Deploying BFFX with Coolify

[Coolify](https://coolify.io/) is an open-source, self-hosted Platform-as-a-Service (PaaS) that serves as an alternative to Heroku or Render. It runs on your own VPS and provides a beautiful dashboard to manage applications, databases, and cron jobs.

This guide walks you through setting up a BFFX application on a server managed by Coolify.

---

## 1. Prerequisites

1. A VPS running Coolify (see [Coolify Installation Guide](https://coolify.io/docs/installation)).
2. Your BFFX project pushed to a Git repository (GitHub, GitLab, or Gitea).
3. The codebase must contain the standard production `Dockerfile` generated by running `bffx deploy init`.

---

## 2. Deploying the Application

### Step 1: Create a New Resource
1. Open your Coolify dashboard.
2. Select your Project and Environment.
3. Click **+ Add New Resource** and select **Application**.
4. Choose your Git source (e.g. **GitHub App** or **Public Git Repository**).
5. Select your repository and target branch.

### Step 2: Configure the Build settings
1. Under **Build Pack**, select **Dockerfile**.
2. Set **Dockerfile Path** to `Dockerfile` (relative to repository root).
3. Under **Ports**, map port `8080` (expose the container port `8080`).

---

## 3. Environment Variables

Coolify handles secrets securely via its dashboard. Add the following key-value pairs in the **Variables** section of your application configuration:

* `BFFX_ENV`: `production`
* `PORT`: `8080`
* `BFFX_JWT_SECRET`: *(Generate a strong 32-character key)*
* `BFFX_ADMIN_SESSION_KEY`: *(Generate a strong 32-character key)*
* `BFFX_APP_SECRET`: *(Generate a strong 16-character key)*

---

## 4. Persistent Storage (SQLite Mode)

If your primary store mode is set to `sqlite`, you **must** configure persistent volumes in Coolify to ensure the SQLite database persists across container updates:

1. In the application settings, go to the **Storage** tab.
2. Add a new volume mount:
   * **Volume Name**: `bffx_db_volume` (or any unique name)
   * **Mount Path inside Container**: `/app/.bffx/data`
3. Click **Save**.

This mounts a persistent Docker volume on `/app/.bffx/data/`, which keeps your SQLite `app.db` file safe when the application container restarts or redeploys.

---

## 5. Connecting a Postgres Database (Postgres Mode)

If your BFFX application uses Postgres, you can provision a Postgres database directly in Coolify and link it to your app:

1. Click **+ Add New Resource** -> **Database** -> **PostgreSQL**.
2. Once provisioned, copy the internal PostgreSQL database URL (e.g. `postgresql://postgres:password@postgresql:5432/db`).
3. Set this URL as the value of the `DATABASE_URL` environment variable under your application's **Variables** tab.
4. Set `BFFX_STORE_MODE=postgres` in your variables as well.

---

## 6. Healthchecks & Rollback

Coolify reads the `HEALTHCHECK` block defined in the BFFX production Dockerfile:

```dockerfile
HEALTHCHECK --interval=15s --timeout=5s --start-period=60s --retries=8 \
  CMD wget -qO- http://localhost:8080/health || exit 1
```

1. Coolify uses this to run healthchecks on the newly built container before routing traffic.
2. If the healthcheck fails, the new build is rejected, and traffic stays on the previous container (built-in zero-downtime rolling update protection).
3. Rolling back to a previous deploy is as simple as clicking **Redeploy** on a previous deployment log from the dashboard.
